# ServiceM8 historical review: source contracts

Checked: 23 October 2026. Purpose: support the owner's authorised read-only review through RGTools, across all staff and from the earliest accessible retained records to the run cutoff. This document checks public contracts only; no customer API calls or credentials were used. It does not enable Office Agent output or close its Diary gate.

## What “from day 1” can establish

Exhaust each authorised source collection without a recent-date or current-status restriction. Report the earliest observed record per source, the extraction start/end, failures and excluded content. This establishes **accessible retained source coverage**, not proof that the account's original first day is preserved, deleted content can be recovered, or every UI Diary entry is represented. ServiceM8 documents separate REST resources; the Diary endpoint itself is create-only. Existing RGTools findings remain applicable: [read coverage](../../../rgtools/docs/research/servicem8-job-diary-read-coverage.md) and [contract decision](../../../rgtools/docs/research/servicem8-job-diary-contract-decision.md). Those sibling paths are reference locations, not dependencies of this collection. [REST overview](https://developer.servicem8.com/docs/rest-overview), [Diary contract](https://developer.servicem8.com/docs/posting-an-add-on-job-diary-item).

## Read resources

All paths below are relative to `https://api.servicem8.com/api_1.0`. Scopes describe OAuth contracts; RGTools uses its existing authorised API-key connection. API keys do not support staff impersonation. Existing account permissions must be respected. [Authentication](https://developer.servicem8.com/docs/authentication).

| Source and list path | Read scope | Meaning and review limit |
| --- | --- | --- |
| [Jobs](https://developer.servicem8.com/reference/listjobs.md): `GET /job.json` | `read_jobs` | Current record, description, quote/invoice flags, milestone dates, creator and completion actor. Include Quote, Work Order, Completed and Unsuccessful. Current state is not a transition log. |
| [Staff](https://developer.servicem8.com/reference/liststaffmembers.md): `GET /staff.json` | `read_staff` | UUID/name/role mapping. Include inactive staff for historic joins; preserve unknown UUIDs. Current role/name does not establish the person's role at the event date. Omit location/contact fields from analytical outputs unless needed. |
| [Notes](https://developer.servicem8.com/reference/listnotes.md): `GET /note.json` | `read_job_notes` | Join `related_object='job'` and `related_object_uuid`. Text and action-required/completion evidence. `edit_by_staff_uuid` is the **last modifier**, not guaranteed original author. Do not silently assign note authorship from it. |
| [Email](https://developer.servicem8.com/reference/listemailmessages.md): `GET /email.json` | `read_email` | Merged inbound/outbound job communications: UUID, job link, direction, timestamp, `sent_by_staff_uuid`, subject, `message_text`, `message_html`, attachment UUIDs and outbound open/bounce facts. Opening is not acceptance or comprehension. Missing/unreadable body remains a coverage gap. |
| [SMS](https://developer.servicem8.com/reference/listsmsmessages.md): `GET /sms.json` | `read_sms` | Merged inbound/outbound job communications with UUID, job link, direction, timestamp, staff sender field and `message`. Not all external phone conversations. |
| [Job activities](https://developer.servicem8.com/reference/listjobactivities.md): `GET /jobactivity.json` | `read_schedule` | Join `job_uuid`, `staff_uuid`; scheduled and recorded activity flags, start/end and modification data. Booked work is not proof it happened; recorded time is not proof of quality or completion. |
| [Attachments](https://developer.servicem8.com/reference/listattachments.md): `GET /attachment.json` | `read_attachments` | Job links, name/type/source, creator, timestamp and metadata; quotes/invoices/photos are Attachment records. **Metadata is not file content**. OCR/extracted information is not guaranteed complete. |
| [Job payments](https://developer.servicem8.com/reference/listjobpayments.md): `GET /jobpayment.json` | `read_job_payments` | Job link, timestamp, amount/method, recorder, deposit flag and receipt reference. A payment record alone does not prove bank reconciliation or all accounting adjustments. |
| [Form responses](https://developer.servicem8.com/reference/listformresponses.md): `GET /formresponse.json` | `read_forms` | `regarding_object`/UUID job link, submitted `field_data`, submitting staff and generated document UUID. Explicitly UTC submission timestamp. Field answers may still need form definitions/context. |
| [Allocations](https://developer.servicem8.com/reference/listjoballocations.md): `GET /joballocation.json` | `read_schedule` | Job/staff links, allocating actor, allocation window/date, allocated/read/completed/expiry timestamps. Allocation completion is not necessarily job completion. Several acceptance and duration fields are deprecated. |
| [Knowledge articles](https://developer.servicem8.com/reference/listknowledgearticles.md): `GET /knowledgearticle.json` | `read_knowledge` | Candidate existing procedures: title/content/type/tags/relationships and edit date. This is current article content, not historical policy revisions or automatic proof of management approval. |

Resource schemas and detail-read definitions are embedded in each linked `.md` page's first-party OpenAPI JSON. Endpoint paths must follow those contracts rather than assumed naming. In particular, [Note detail](https://developer.servicem8.com/reference/getnotes.md) specifies `/dbonote/{uuid}.json`, while [Attachment detail](https://developer.servicem8.com/reference/getattachments.md) specifies `/dboattachment/{uuid}.json`. Validate these documented asymmetries before relying on detail fallback. Email and SMS detail reads are `/email/{uuid}.json` and `/sms/{uuid}.json`. [Email detail](https://developer.servicem8.com/reference/getemailmessage.md), [SMS detail](https://developer.servicem8.com/reference/getsmsmessage.md).

## Pagination, inactive records and cutoff

- For standard REST collections, start `cursor=-1`, follow `x-next-cursor`, and finish only when the header is absent after a successful valid response. Pages contain up to 1,000 records. A short page, fixed page cap, repeated cursor, parse error, HTTP error or interruption is not successful exhaustion. Save per-source page/record/duplicate counts and the resume cursor. [Pagination](https://developer.servicem8.com/docs/pagination).
- Email and SMS explicitly define their own cursor walks with the same response header and `limit` from 1 to 1,000 (default 1,000). Their filters support only equality on direction, related object and related-object UUID joined with `and`. Do not send generic date or `active` filters to these endpoints. [Email contract](https://developer.servicem8.com/reference/listemailmessages.md), [SMS contract](https://developer.servicem8.com/reference/listsmsmessages.md).
- Standard resources support `eq`, `ne`, `gt`, `lt`, at most ten `and` conditions; no `or`, `ge` or `le`. To include both activity flags explicitly, walk `active eq 1` and `active eq 0` separately where that field is supported, then deduplicate by source and UUID. No status filter should remove unsuccessful or completed jobs. Deleted Jobs/Notes are documented as inactive records still accessible by API; this does not promise recovery of purged records or historic versions. [Filtering](https://developer.servicem8.com/docs/filtering), [Job deletion semantics](https://developer.servicem8.com/reference/deletejobs.md), [Note deletion semantics](https://developer.servicem8.com/reference/deletenotes.md).
- Set an exact run cutoff with timezone when extraction begins, labelled in Pacific/Auckland for the user on 23 October 2026. Preserve raw dates and source-specific normalized dates. General timestamps are account-local unless otherwise stated; FormResponse submission time is explicitly UTC. Confirm the ServiceM8 account timezone rather than assuming it matches the desktop. [Field types](https://developer.servicem8.com/docs/field-types), [FormResponse schema](https://developer.servicem8.com/reference/listformresponses.md).
- The checked contracts do not promise a transactional historical snapshot while pages are being read. Record collection intervals and edits after cutoff; do not pretend current mutable text reconstructs its earlier version. Since email/SMS cannot date-filter, collect their pages first and apply event cutoff locally. Future bookings found now can be retained as scheduled commitments, clearly distinguished from events already performed. These are extraction design rules derived from the contracts above.

## Content, dates and staff attribution

Job `date` is described as created **or scheduled**; do not label it a precise account-start date. `quote_date`, `work_order_date`, `completion_date`, and `unsuccessful_date` describe status milestone dates on the current Job; they do not enumerate every revision/reopening. `edit_date` is last record modification, not latest Diary activity. Legacy Job payment fields are explicitly unused; use JobPayment instead. The Note schema misleadingly describes `create_date` as last-modified time too, so retain the raw field without asserting independent creation semantics until verified. [Job schema](https://developer.servicem8.com/reference/getjobs.md), [Note schema](https://developer.servicem8.com/reference/getnotes.md).

Keep actor roles distinct: Job creator, completion actor, outbound sender, note editor, activity assignee, allocator, form submitter and payment recorder are different claims. `sent_by_staff_uuid` may be absent; leave attribution unknown rather than infer from a signature/name. Job ownership and current assignee do not prove authorship of every communication. These interpretation rules follow the field-specific contracts in the source table.

Attachment file retrieval is separate: `GET /attachment/{uuid}.file` returns a 302 redirect to temporary file storage. Do not forward the ServiceM8 credential to the redirect host. Record each content retrieval/parse failure; a metadata-only extraction cannot support claims about dimensions, scope, exclusions, photos or plans inside the file. [Download contract](https://developer.servicem8.com/reference/downloadattachmentfile.md).

## Operational limits and conclusions

The first-party OpenAPI `info.description` documents **180 requests/minute and 20,000/day**, per add-on per account, with HTTP 429 for exceeded minute/day budgets. Leave headroom for RGTools' normal activity and resume after throttling; day exhaustion is not solved by rapid retries. API-key limits should be observed in actual responses rather than assumed independent of the shared connection. [Published OpenAPI metadata](https://developer.servicem8.com/reference/listjobs.md).

Collection exhaustion supports statements such as “these accessible email records repeat this pattern.” It does **not** establish a complete UI Diary, prove absence of a call or subsequent reply, validate current policy, or authorise autonomous client messages. Treat inferred practices as candidate rules with dated, source-linked evidence, exceptions and Roxy/team confirmation. The read-only historical review can proceed under that bounded claim while full Diary parity remains unresolved. [Diary create-only contract](https://developer.servicem8.com/docs/posting-an-add-on-job-diary-item), [REST/UI mapping](https://developer.servicem8.com/docs/rest-overview).
