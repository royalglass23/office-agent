# RG-380: historic Job Diary read paths

Research date: 20 October 2026
Method: current first-party ServiceM8 developer documentation only; no Royal Glass API or UI probe.

## Finding

No documented read-only OAuth endpoint found that lists the **complete historic Job Diary** or establishes the exact timestamp and stable Diary-item ID of the visible **Job Created** and **Service** entries. This is a documentation finding, not proof that ServiceM8 has no internal or separately supported read path. The [ServiceM8 API index](https://developer.servicem8.com/llms.txt) lists a Diary **create** endpoint, while its [Diary guide](https://developer.servicem8.com/docs/posting-an-add-on-job-diary-item) explicitly says that capability cannot list or retrieve Diary items, including items the add-on created. Do not call `GET /diary.json` on the assumption that POST implies GET.

Other fields show current Job state or specific milestones. | `date` is not documented as the exact historic Job Created Diary timestamp; the Job UUID does not identify that Diary row. |

The current eight-scope grant does not contain `read_job_admin_activity`; seeking it would require a manifest/scope change and a new OAuth grant, followed by same-staff, authorised-job parity testing. No speculative live request was made. |
| [Job Activity list](https://developer.servicem8.com/reference/listjobactivities), `read_schedule` | `jobactivity.json` contains a Job UUID, UUID, scheduled/recorded flags and start/end times. The separate Job Admin Activity path above must not be confused with this endpoint. |
| [Job Material list](https://developer.servicem8.com/reference/listjobmaterials) / [Job Material Bundle list](https://developer.servicem8.com/reference/listjobmaterialbundles), `read_job_materials` | Job-linked quote/invoice line items and bundles have their own UUIDs and `edit_date`. The [REST overview](https://developer.servicem8.com/docs/rest-overview) describes JobMaterial as quote/invoice line items. | A material or labour line may relate to a service sold, but neither reference documents a historic Diary **Service** event, event timestamp, or matching Diary ID. `edit_date` is modification time, not an event creation timestamp. |

| [Event webhook subscription](https://developer.servicem8.com/reference/post_event_webhook_subscription) / [webhook overview](https://developer.servicem8.com/docs/webhooks-overview) | Includes `job.created` and other event notifications; webhook delivery is to a configured callback when events occur. The overview says object-change payloads may contain time/UUID but not the record content. | Future event capture cannot backfill historic Job Created/Service rows for R260766 or R260609, nor prove a complete historic Diary. |

## Decision for this slice

Keep the RG-380 full-Diary and Job-answer gate closed. The two approved Jobs' note/email/activity/attachment inventory comparisons do not resolve these item IDs/timestamps or body/file parity. Ask ServiceM8 developer support whether an **approved, read-only OAuth** historical Job Diary or Job Admin Activity response includes Job Created and Service rows, their exact Diary timestamps, stable row UUIDs and job linkage, and what scope and staff-impersonation semantics apply. If support identifies a read path, add it only after a scoped implementation and same-staff UI/API parity check. [Diary create-only guide](https://developer.servicem8.com/docs/posting-an-add-on-job-diary-item); [Job Admin Activity reference](https://developer.servicem8.com/reference/listjobadminactivities).
